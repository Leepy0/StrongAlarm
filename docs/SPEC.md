# StrongAlarm v0.1 스펙

## 1. 목표

- 알람이 울리면 **실제로 걸어야** 해제되는 알람 (워치 착용 수면 전제)
- 연차·여행·공휴일·주말은 캘린더로 자동 스킵, 특근은 자동으로 울림
- 판정이 틀려 휴무일에 울려도 **휴무 버튼(5초)** 으로 즉시 종료
- SmartThings 조명: 알람 전 디밍, 미해제 시 스위치 점등, 해제 후 자동 소등

## 2. 결정 사항

| # | 항목 | 결정 |
|---|------|------|
| 1 | 해제 조건 | 걸음 30보 (설정에서 ±5, 10~200) |
| 2 | 스누즈 | 없음 |
| 3 | 미해제 시 | 볼륨 70% → 5분마다 85% → 100% 유지, 종료 없음 |
| 4 | 디밍 | 알람 15분 전 시작, 30초 간격, 1% → 100% 선형 |
| 5 | 스위치 점등 | 울림 후 5분 미해제 시 켜기 (점멸 없음) |
| 6 | 해제 후 조명 | 5분 뒤 자동 소등 (앱이 켠 조명만) |
| 7 | 특근 시각 | 평일과 동일한 단일 시각 (다르면 일회성 변경 사용) |
| 8 | 판정 확정 | 23시 안내 + 디밍 시작 전 재판정 + 울림 직전 재판정 |
| 9 | 공휴일 소스 | 폰 캘린더의 공휴일 캘린더 (예: Google "대한민국의 휴일") |
| 10 | 삼성 헬스 | v0.1 제외 (워치 앱이 걸음 실시간 전송) |
| 11 | 워치 앱 | 진동 + 걸음 전송만 (휴무 버튼은 폰에만) |
| 12 | 배포 | 개인 사이드로드 (Play 정책 미고려) |
| - | 알람 개수 | 단일 시각 1개 + 날짜별 일회성 시각 변경 |
| - | 태그 스캔 미션 | 없음 |
| - | 재수면 감시 | 없음 |
| - | 휴무 버튼 | 5초 길게 누르기, 누르는 동안 소리·진동(폰·워치) 일시정지, 횟수 제한 없음 |
| - | 약한 재알람 | 없음 |

## 3. 휴무 판정

우선순위 (위가 이김):

1. **일회성 변경** — 해당 날짜에 시각이 지정돼 있으면 무조건 그 시각에 울림
2. **근무 키워드** (기본 `특근`) — 주말·공휴일이어도 울림
3. **휴무 키워드** (기본 `여행`, `연차`, `휴무`, `디데이`, `휴가`) — 스킵. 단 **제외 키워드**(기본 `신청`, `마감`)가 같이 있으면 무시
4. **공휴일 캘린더** 일정 — 스킵. 단 `어버이날`, `스승의 날`, `식목일`, `제헌절` 같은 비공휴 기념일은 무시
5. **주말** — 스킵
6. 그 외 — 울림

세부 규칙:

- 키워드는 **제목 포함** 매칭, 공백·대소문자 무시. 설정 화면에서 칩으로 추가·삭제
- 여러 날에 걸친 일정(여행 등)은 알람 날짜와 **겹치면** 적용
- 키워드 판정 대상 캘린더를 선택 가능 (공유 캘린더의 배우자 일정 배제). 미선택 = 전체
- 공휴일 캘린더는 키워드 판정에서 제외 (공휴일 규칙으로만 처리)
- 캘린더를 읽을 수 없으면(잠금 해제 전 재부팅 등) 최근 판정 캐시 사용, 캐시도 없으면 **울림** (fail-safe)

## 4. 타임라인 (07:00 알람 기준)

```
전날 23:00  내일 판정 안내 알림  [시각 변경] [그래도 울리기(스킵일 때)]
06:45       재판정 → 울림이면 조명 스냅샷 저장 후 디밍 시작 (30초마다 1→100%)
07:00       재판정 → 울림 시작 (소리 70%, 폰·워치 진동, 걸음 카운트)
07:05       미해제면 스위치 점등, 볼륨 85%
07:10       볼륨 100% (이후 유지)
걸음 30보   해제 → 5분 뒤 앱이 켠 조명 소등
휴무 버튼   5초 유지 → 즉시 종료 + 조명 알람 전 상태로 복구
```

## 5. 구성

```
core/   순수 Kotlin: 휴무 판정(DayOffJudge), 다음 알람 계산(AlarmPlanner), 램프, 워치 프로토콜  ← 단위 테스트
app/    폰 앱 (Compose)
wear/   Wear OS 앱 (진동 + 걸음 전송)
```

### 폰 앱 주요 클래스

| 클래스 | 역할 |
|--------|------|
| `AlarmScheduler` | 다음 알람 계산·등록 (`setAlarmClock`), 디밍·23시·자동 소등 정확 알람, 판정 캐시 |
| `AlarmReceiver` / `BootReceiver` | 알람 트리거, 부팅(잠금 해제 전 포함)·시간 변경 시 재등록 |
| `AlarmService` | FGS(`systemExempted`). 디밍 → 울림 → 일시정지 → 종료 상태 관리 |
| `AlarmActivity` | 잠금화면 위 알람 화면, 5초 홀드 버튼 |
| `CalendarChangeJob` | 캘린더 변경 감지 → 재계산 |
| `SmartThingsAuth/Client` | OAuth(authorization code + refresh), 기기 조회·명령 |
| `LightController` | 스냅샷, 디밍, 스위치, 복구/소등 |

### 폰 ↔ 워치 메시지 (`WearProtocol`)

| 경로 | 방향 | 내용 |
|------|------|------|
| `/strongalarm/start` | 폰 → 워치 | 울림 시작, payload = 목표 걸음 |
| `/strongalarm/pause`, `/resume` | 폰 → 워치 | 휴무 버튼 누르는 동안 진동 정지 |
| `/strongalarm/stop` | 폰 → 워치 | 종료 (유실 대비 3회 전송) |
| `/strongalarm/steps` | 워치 → 폰 | 누적 걸음 |

판정 걸음 = max(폰 걸음, 워치 걸음). 워치 미연결이면 폰 걸음만 사용.
워치는 STOP 미수신 대비로 목표 걸음 달성 또는 60분 경과 시 스스로 종료.

## 6. 신뢰성 대책

- 모든 저장 데이터는 **기기 보호 저장소** → 재부팅 후 잠금 해제 전에도 알람 동작
- 알람 소리: `USAGE_ALARM`, 내장 스피커 우선 (블루투스·이어폰 연결 시에도 스피커), 알람 볼륨 강제 설정 후 종료 시 원복
- 기본 알람음 재생 실패 시 합성 비프음
- `START_STICKY` + 세션 상태 저장 → 프로세스 재시작 시 울림 복구
- 조명·네트워크 실패는 알람과 격리 (best-effort)
- 폴드: 알람 화면은 접기/펼치기 시 재생성하지 않고, 상태는 서비스가 보관
